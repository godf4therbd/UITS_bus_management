The Challenge

Problem Statement

Students had no real-time visibility into bus locations, delays, or capacity — leading to missed buses and long wait times.

Admins managed bus operations through phone calls and manual processes with no centralized system.

There was no structured way for students to report issues (overcrowding, breakdowns, driver misconduct).

Notification of bus delays or cancellations relied on word-of-mouth, causing widespread confusion.

Goal: Build a unified digital platform that connects students, drivers, admins, and management in real time.

What It Does

Key Features

🔔

Push Notifications

Real-time alerts sent to students about delays, cancellations, and bus status changes via Firebase Cloud Messaging.

📊

Live Bus Status

Admins update bus status (On Time / Delayed / Full) instantly. Students see changes reflected in real time.

📷

QR Code Scanning

Students scan a QR code to verify their assigned bus and view route information instantly.

🚨

Issue Reporting

Students submit reports for overcrowding, breakdowns, or driver issues. Admins track and resolve them.

🔐

Role-Based Access

Five distinct roles — Super Admin, Admin, Moderator, Driver, Student — each with a tailored dashboard.

🌙

Dark Mode

Full dark and light mode support for comfortable use in all lighting conditions.

Access Control

Role-Based Dashboards

Super Admin

Manages the entire fleet — adds/removes buses, assigns admins and moderators, views all reports, generates QR codes.

Admin (Bus Admin)

Manages assigned buses, updates bus status, sends notifications to students, resolves student reports.

Moderator

Monitors operations, views reports and notifications across buses, assists in issue resolution.

Driver

Views assigned route and stops, receives notifications, updates availability status.

Student

Scans QR code to verify bus, receives push notifications, reports issues, views real-time bus status.

Security Measures

  • Firestore rules require authenticated users
  • Firebase session verified on every app load
  • Credentials removed from git history
  • Dev-only logging (no production leaks)

Performance Optimizations

  • Mock user login is instant (local check first)
  • Firestore reads run in parallel (Promise.all)
  • useMemo & useCallback reduce re-renders
  • Query results limited to 50 records
